Parallel is a hiring platform that matches job seekers with hiring teams. I joined in May 2023 as a full stack engineer on a remote team spread across US, Canadian and European time zones, and became the person who owns the infrastructure. Client work, so no screenshots. This is what I can say.

The platform

Every piece of AWS the product runs on is Terraform: the ECS services, the EC2 instances, the S3 buckets, the load balancer in front, the IAM roles between them. A change to the infrastructure is a reviewed merge request, not a click in the console.

When I arrived there was no pipeline. I set up GitLab CI/CD from scratch so that every service gets the same treatment on every push: run the tests, build the Docker image, deploy it. Operational tasks that used to be done by hand (deployments, maintenance, clean-up) became Bash scripts that anyone on the team can run.

The serverless part

Not everything deserves a long-running container. The event-driven and scheduled workloads (reacting to uploads and queue messages, nightly jobs) run as Lambda functions, six and counting, deployed through the same pipeline and defined in the same Terraform.

The services

I designed, built and deployed five or more backend services and microservices, in whichever language fit: Python with FastAPI and Flask, Node.js in TypeScript, and Go. They expose REST APIs and WebSocket APIs for the real-time product features, and all of them ship in Docker to ECS.

Two of them are worth naming. A high-throughput web scraping and data ingestion service in Flask, and the recommendation services that give end users personalised results in production. On the front end I shipped user-facing features in Next.js and TypeScript, from the UI through to the API integration.

The data layer

I own the PostgreSQL side. The work that matters most is unglamorous: reading query plans, tuning the slow ones, and eliminating N+1 patterns in the ORM code so endpoints stay fast as the data grows. Performance under production load is a thing you keep, not a thing you reach.

RAG in production

The same infrastructure runs the LLM features. I built production RAG (retrieval-augmented generation) systems with LangChain against the OpenAI and Anthropic APIs, with vector search on pgvector where the data already lived in Postgres and on Pinecone where it did not. Because I also own the platform, the AI services get the same pipeline, the same containers and the same monitoring as everything else, instead of living in a notebook somewhere.

The through-line of this job: I write the service, I write the pipeline that ships it, and I write the Terraform it runs on. When something breaks at 2am in another time zone, there is no handoff between "the app" and "the infra". It is one person's problem, and that person can fix it.
