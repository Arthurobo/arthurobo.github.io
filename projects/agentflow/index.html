AgentFlow

Start a coding-agent terminal from your phone, leave it running, come back to the same terminal later from any paired device. A Go daemon, a tunnel, and no passwords.

I run Claude Code all day. The thing I kept wanting was to check on a long task, or kick off a new one, from my phone while away from the desk, and to come back to the same terminal, not a new session. AgentFlow is that. It does not replace the agents: it runs the claude and opencode you already have, logged in as you, in real PTYs, and serves a web UI for talking to them.

Getting in

Remote access is the whole point, and the part that has to be right. By default the account service gives each machine its own Cloudflare tunnel at a stable address like https://quiet-harbor-4821.useagentflow.xyz. Nothing to set up and no account needed: the daemon runs cloudflared itself, downloading a pinned, SHA-256-verified release if there is none on the path.

If you would rather nothing went through servers I run, AF_REMOTE=tailscale uses Tailscale instead. AgentFlow embeds its own Tailscale node with tsnet, so there is no install and no root, just a one-time browser sign-in. Or it can use the Tailscale already on the computer. Or AF_REMOTE=off keeps everything on localhost.

Whichever way in, only paired devices see anything. To anyone else the address shows the pairing page and nothing but 404s. A phone pairs once, with a one-time QR code or by tapping Request access and having the 4-digit code approved on the computer, and gets its own token that can be revoked on its own.

Running in the background

A terminal you come back to has to outlive the browser tab, so the daemon is a real service: a systemd user unit on Linux, a launchd agent on macOS, a per-user Scheduled Task on Windows. None of them need admin. On Windows the terminals are ConPTY instead of a Unix PTY, and the build is the same Go binary. The CLI talks to the running daemon over an owner-only Unix socket, so agentflow pair, approve, revoke and remote status work the same whether the daemon is the service or a foreground agentflow serve.

Shipping it

End users need neither Go nor Node. make build exports the Next.js UI and embeds it in the binary; GitHub Actions builds release archives for every OS and CPU. The installer downloads the right one, verifies its SHA-256 against the release's checksums.txt and, when cosign is installed, the signature on that file. A failed signature aborts the install. agentflow update does the same dance for upgrades, and agentflow uninstall --purge lists what it will remove and asks first.

The account service

agentflow-cloud is deliberately small. One Go binary serves a JSON API, a dashboard in Go templates with vendored htmx (no JavaScript build step), and a health check. It signs people in with an emailed 6-digit code, emails them their machine's address when it changes, and provisions the Cloudflare named tunnels through Cloudflare's API, storing only a hash of the machine's provisioning secret. Codes and session tokens are hashed at rest; the schema is one migration with timestamps and an update trigger on every table, and a test checks that stays true. It never receives device tokens, pairing tokens or terminal data, so nothing stored there grants access to a machine.

The honest part

A paired device can run any command as you. The agent terminals run with claude --dangerously-skip-permissions (OpenCode: --auto), because that is what makes them useful from a phone. The README says so in a warning box, SECURITY.md spells out the model, and the default Cloudflare transport is documented as one where Cloudflare terminates TLS and can see the traffic. Pair only devices you control.
