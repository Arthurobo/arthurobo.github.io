Saidic gives a business an AI assistant for its website, or a hosted page at saidic.com with a QR code if it has no website. Visitors get answers drawn only from the business's own knowledge, and the assistant can perform actions against the business's APIs, with the customer's consent. A human can take over any conversation from a live Messages dashboard. Team roles (Owner, Admin, Manager, Editor, Viewer), webhooks, identity verification and a one-line embed round it out.

How an answer is made

Everything a business gives the assistant becomes passages: its profile, questions and answers, uploaded files, verified websites the crawler reads, and documents pushed by its own programs through an API key. Retrieval is hybrid. Vector search on pgvector, Postgres full-text search and exact matching for part numbers and codes are fused with reciprocal rank fusion, and the whole thing is measured against a labelled question set so answers stay grounded in the right sources.

Each turn is routed by a small typed decision model. The reply is drafted by a frontier model through OpenRouter, then checked against the passages it cites before anything is sent. Every turn is logged with its intent, what was retrieved, the checks it passed, its latency and its cost, and the questions that could not be answered feed a knowledge-gap list the business can act on. Prompts live as linted YAML, and an evaluation harness runs the whole thing end to end.

Actions, and why the model never decides

An action is an endpoint the business configures: a URL, a method, the parameters to collect, a credential. The LLM never decides to act. A small model answers narrow typed questions with probabilities, deterministic thresholds decide whether an action starts and whether a "yes" counts, and the customer's confirmation is bound to the exact message and a fingerprint of the values, so a confirmation cannot be replayed against different data. Visitor text is marked untrusted throughout.

Credentials are encrypted at rest with AES-256-GCM and never returned by the API. Every outbound call to a business's URL goes through a security gate: a protocol allowlist, internal-address and SSRF blocking that holds on every redirect hop, and timeout and size limits. The assistant's behaviour is validated with an adversarial test suite covering prompt injection, out-of-scope requests and false promises, and that suite runs before a release.

Realtime and operations

Three WebSockets, for the visitor, the staff dashboard and the agent, fan out over Redis pub/sub so any API instance can serve any conversation. Background work runs on Redis-backed arq workers. Production and staging run on Docker Compose behind Cloudflare and nginx, with GitHub Actions CI/CD, Alembic migrations and R2 for storage. Every API endpoint is covered by automated contract tests.

The consolidation

Saidic did not start this way. The earlier version was a Django REST backend with Celery and Celery beat, a Go service for WebSockets and tracking, a FastAPI "Logic Engine" for the chat agent with its own Celery, a Research Engine with its own API, two Redis instances, Elasticsearch, and an in-memory FAISS index. It worked, and it was seven things to deploy, monitor and keep in step.

The rule of the consolidation was that behaviour stays identical: the same paths, request and response shapes and status codes, so the two front ends did not have to change. A small compatibility layer reproduces the old framework's validation messages and pagination down to the wording, and every deliberate difference is recorded with its reason. Elasticsearch and FAISS are gone: directory search is Postgres full-text search and similarity is pgvector. Inside the backend, each module has its models, its service and its router, and the boundaries are enforced by a script that runs with the tests.

How it was built

I wrote the architecture and made the retrieval, safety and measurement decisions, and directed AI coding agents through most of the implementation, the same way I run them in AgentFlow. The first version started in my repo in 2025; the rebuild launched in October 2026, and the first businesses came on through a friend onboarding his clients.
