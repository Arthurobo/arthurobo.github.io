Parallel is a hiring platform that matches job seekers with hiring teams. I joined in May 2023 on a remote team spread across US, Canadian and European time zones, and over three and a half years became the engineer who owned the platform as well as the services on it. Client work, so no screenshots. This is what I can say.

The platform

Every piece of AWS the product runs on is Terraform IaC: ECS Fargate services, EC2, Lambda, SQS queues, EventBridge rules, S3, the load balancer in front, ECR, and the IAM roles between them. A change to the infrastructure is a reviewed merge request, not a click in the console.

When I arrived there was no pipeline. I set up GitLab CI/CD from scratch, so every service gets the same treatment on every push: run the tests, build the Docker image, deploy it. Later I maintained GitHub Actions workflows for the same jobs and moved CI/CD to short-lived credentials with GitHub OIDC and least-privilege IAM, so no static cloud keys live in the pipeline. Operational tasks that used to be done by hand became Bash scripts anyone on the team can run.

Two things I am particularly glad shipped: per-pull-request preview environments on ECS Fargate Spot with PII-masked database branches, so a reviewer can click a link instead of pulling a branch, and the decommissioning of legacy environments and databases with Terraform, backed by a full dependency audit, which simplified the architecture and cut infrastructure cost.

Performance

I led the performance optimisation of the platform's highest-traffic APIs. The heavy pages had drifted into timeouts as the data grew, and the fix was never a bigger box: I redesigned how those endpoints fetched their data and how services talked to each other, and brought the critical endpoints from timeouts to sub-second response times. I own the PostgreSQL data layer and treat keeping queries performant under production load as a thing you keep, not a thing you reach.

Reliable background work

I re-architected background processing around AWS EventBridge and SQS, so scheduled jobs and the email, SMS and push notifications are reliable and idempotent: a job runs once, a message is sent once, and a retry is safe. The multi-channel notification delivery runs on Twilio, SendGrid and Firebase with compliance and failover handling built in. Six and counting Lambda functions handle the event-driven and scheduled workloads, deployed through the same pipeline and defined in the same Terraform.

Security and observability

I led the API and cloud security hardening: authentication enforced across services, unused endpoints retired, and the pipeline moved to short-lived OIDC credentials with least-privilege IAM. Alongside it I strengthened production observability and data protection with Sentry, CloudWatch alarms and automated PII masking, so the team sees a problem before a customer does and test data never carries real personal information.

The services

I designed, built and deployed five or more backend services and microservices in whichever language fit: Python with FastAPI and Flask, Node.js in TypeScript, and Go. They expose REST and WebSocket APIs for the real-time product features, and all of them ship in Docker to ECS. On the front end I shipped user-facing features in Next.js, React and TypeScript, owning the UI implementation through to the API integration. When I rolled off I left infrastructure READMEs, runbooks and a full platform handoff behind.

RAG in production

The same platform runs the LLM features. I built production RAG (retrieval-augmented generation) systems with LangChain against the OpenAI and Anthropic APIs, with vector search on pgvector where the data already lived in Postgres and on Pinecone where it did not, and shipped recommendation systems that give end users personalised results. I also improved the reliability of a production LLM scoring pipeline on SQS and OpenAI, so its results are consistent and land exactly once under load. Because I also owned the platform, the AI services got the same pipeline, containers and monitoring as everything else, instead of living in a notebook somewhere.

The through-line of this job: I write the service, I write the pipeline that ships it, and I write the Terraform it runs on. When something breaks at 2am in another time zone, there is no handoff between "the app" and "the infra". It is one person's problem, and that person can fix it.
